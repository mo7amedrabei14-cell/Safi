# سياسة السجلات والتشخيص (`docs/LOGGING.md` — القسم 15)

## 1. القاعدة الذهبية للخصوصية (القاعدة الصارمة رقم 4)
- **لا تغادر بيانات المستخدم جهازه أبدًا** في أي سجل أو تقرير أعطال أو قياس عن بُعد (`telemetry`).
- **يُحظر قطعيًا** تسجيل:
  - قيم الخلايا (`cell values`) أو أي عينة منها.
  - أسماء الملفات (`file names`) أو المسارات الكاملة للمستخدم.
  - أسماء الأعمدة (`column names`).
  - كلمات السر أو المفاتيح أو الرموز أو عناوين البريد الإلكتروني الخام.

## 2. هيكل سطر السجل المعتمد (`JSON Lines`)
كل حدث يُسجّل بصيغة JSON منظمة تحتوي فقط على:
- `timestamp`: التوقيت بصيغة ISO-8601 UTC.
- `level`: مستوى السجل (`info`, `warn`, `error`).
- `event`: اسم الحدث المعتمد من القسم 19.5 (`domain.action.result` مثل `import.started`, `import.completed`, `import.failed`, `clean.step.applied`, `export.completed`).
- `code`: رمز الخطأ المعتمد من `errors.toml` (`SF-<DOMAIN>-<NNN>`) عند وجود تحذير أو خطأ.
- `request_id` / `trace_id`: معرّف التتبع الفريد للجلسة أو الطلب.
- `metrics`: أعداد مجردة فقط (مثل `row_count`, `col_count`, `duration_ms`).

## 3. المكدس المركزي للسجلات (الشريحة S4/S5 — القسم 20.4)
- التجميع والنقل: **OpenTelemetry** + **Vector**.
- التخزين والبحث الفوري: **VictoriaLogs** (أخف بـ 10 مرات في استهلاك الذاكرة من Loki).
- العرض والتنبيهات: **Grafana** + **GlitchTip** المستضاف ذاتيًا.
