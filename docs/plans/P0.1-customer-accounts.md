# خطة P0.1 — قاعدة بيانات العملاء والاشتراكات والصلاحيات

## النطاق
تنفيذ طبقة البيانات والصلاحيات فقط، دون واجهات HTTP جديدة ودون تغيير ملفات العملاء المحلية.

## ما يُبنى
1. حالة الحساب: `users.suspended_at` مع اشتقاق `active / suspended / deleted` من `suspended_at` و`deleted_at`.
2. كتالوج الخطط المطابق لـ `config/business.json`: `individual_monthly`, `individual_annual`, `organization_seat`.
3. أسعار بعملتين: `plan_prices` (USD cents وEGP piastres) لكل خطة وفترة.
4. سجل اشتراكات غير قابل للتعديل: `subscription_events` بأنواع `created / renewed / plan_changed / canceled / reactivated / expired / refunded / trial_extended`.
5. صلاحيات المالك: `OwnerGrant` لا يمكن إنشاؤه إلا بعد `authorize_owner`، وRLS للمالك عبر `app.owner_admin` داخل معاملة فقط.
6. اختبارات وحدة + اختبار PostgreSQL حقيقي تحت دور `NOBYPASSRLS`.

## الثوابت
- كل عميل = مستخدم واحد + Workspace شخصي + عضوية `owner` + اشتراك مستقل.
- لا تُخزَّن محتويات ملفات العملاء في قاعدة البيانات المركزية.
- الخطط المدفوعة تبقى `draft` حتى تُفعَّل حسابات الدفع؛ Free فقط `active` الآن.
- لا Push إلى `main` قبل موافقة المالك.

## معايير القبول
- `verify-migrations.py` يمر ويجد 5 أزواج Up/Down.
- `cargo clippy -D warnings` واختبارات المكتب تمر.
- اختبار PostgreSQL يثبت: المالك يقرأ كل الـWorkspaces، غير المالك يُرفض، الإيقاف/الاستعادة يُحفظان، وحدث الاشتراك يُسجَّل.
- التراجع يعيد الجداول والأعمدة والسياسات إلى ما كانت عليه.
