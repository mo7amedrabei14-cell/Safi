**عقد القبول:** [المهمة](../tasks/STUDIO-Phase-1.md).  
**الشرط السابق:** [تقرير التدقيق](../reports/STUDIO-ARCHITECTURE-AUDIT.md)، خصوصًا AUDIT-01 إلى AUDIT-05.

## 1. حدود التنفيذ

- لا تغيير للحسابات والجلسات والصلاحيات والأجهزة والاشتراكات والخادم وقاعدة البيانات والموقع التسويقي.
- لا صفوف عينات أو أرقام ثابتة في المخرج، ولا حساب حساس في TypeScript، ولا فرع/worktree أو نشر.
- المقترحات أدناه ليست إعفاءً من Arrow/Polars أو wa-sqlite/Glide/Zustand المعتمدة. يُحسم توافقها وأحجام WASM أولًا.

## 2. العقود قبل التنفيذ

- `SourceId`, `DatasetVersion`, `RowId`, `ColumnId`, `MetricId`, `ScenarioId`: هويات مستقرة غير مشتقة من تسميات العرض؛ مصدر أصلي غير قابل للتعديل.
- `DataGraph`: مصادر وتحويلات وأعمدة محسوبة ومؤشرات وسيناريوهات وفهرس dependencies وdirty/cache وإصدار حالة منشور.
- `Expression`: AST محدود، typed، بعقد عمليات ومعنى للفراغ والتقريب والقسمة والصفر/overflow والوحدات؛ رفض المراجع والدورات قبل التنفيذ.
- `VerifiedMetricToken`: جميع حقول المهمة؛ canonical fingerprint منفصل عن timestamp العرض، وDecimal كنص عند حد JS، وحالات verified/stale/unverified/error صريحة.
- `StudioCommand`: `requestId`, `projectId`, `expectedRevision`, فعل ذو payload محدد. النتيجة: revision والمؤشرات المتأثرة أو خطأ SF مسجل؛ لا قبول لرد قديم.
- `StudioProject`: schemaVersion، أصول أصلية، إصدار dataset، سجل تحويلات، calculatedColumns، metrics، scenarios، view bindings. لا bearer tokens.

## 3. وحدات العمل المرتبة

### 1A — تهيئة الأساس وبيئة WASM

- تثبيت أدوات WASM المطابقة للاعتماديات الحالية والتحقق من compilation وتشغيل عامل محلي.
- حسم تمثيل Arrow/Polars وحدود الحجم من خلال build/benchmark فعليين قبل التوسع، لا استبدالهما بنموذج موازٍ.
- الملفات: Cargo manifests/lock المتأثرة وأدوات بناء WASM وحزمة web عند الحاجة، دون تعديل CI أو سياسة أمان محمية بلا تصريح.
- الإثبات: ناتج WASM يعمل في متصفح، لا native cargo test وحده، مع قياس الحجم والذاكرة ونقل Decimal دون فقد.

### 1B — صحة الاستيراد والتحويل

- إصلاح المسؤولية في sf-io/sf-clean وما يستدعيه من sf-arabic لما سيستهلكه DataGraph: قراءة محدودة، فراغات XLSX صحيحة، raw محفوظ، مفاتيح تكرار بنيوية، وتراجع صالح.
- إضافة اختبار فشل قبل كل إصلاح؛ لا ادعاء دعم recipe operation لا ينفذها المحرك.
- الملفات: reader_csv.rs وreader_excel.rs وcleaner.rs وnormalizer.rs واختباراتها حسب العيب المثبت. كشف اختبار الأسماء المركبة ضرورة تنظيف المسافات قبل وصل الاسم لضمان عدم تغيره عند التكرار.
- calamine 0.26.1 يتجاهل mergeCell بلا ref ولا يفك ترميز XML داخل المراجع؛ يعاد استعمال quick-xml 0.31.0 الموجود بالفعل بصورة مباشرة لفحص المراجع وبناء Dimensions منها دون ترقية إصدار أو كتابة محلل XML يدوي. تُفحص الأجزاء المحددة بعلاقات workbook نفسها استقلالًا عن تسميات ContentType، وتُحسب تكلفة نسخ نصوص الدمج فعليًا قبل تخصيص الشبكة. تغييرات Cargo محصورة في علاقة الاعتماد هذه.
- الإثبات: CSV مقتبس/متعدد الأسطر، XLSX به فراغ حقيقي ودمج حقيقي ومراجع دمج غير صالحة، صفوف تتصادم نصيًا، raw قبل/بعد/undo، ونص مطبّع فارغ؛ لا تشغيل ماكرو أو صيغة ملف.

### 1C — DataGraph وtokens

- أنواع مشتركة في sf-core، وتنفيذ التحويلات/الجدولة داخل sf-recipe وفق اتجاه الاعتماد القائم؛ لا dependency cycle عبر sf-clean.
- تعديل الخلايا والمعادلات في transaction: validate → تحديد التأثير → حساب → نشر revision؛ الفشل يترك الحالة السابقة.
- undo/redo كفروقات، مع ثبات هويات الأصل وتحديث المراجع والإصدارات وإبطال tokens.
- cache بمدخلات واعتمادات محددة، وإثبات incremental مقابل full recalculation.
- الإثبات: سلاسل/تفرعات/dag cycle، أعمدة متشابهة الأسماء، تعديلات غير مرتبطة، تبديل مصدر بنفس النتيجة، عبث قيمة/token، overflow/قسمة صفر/نوع غير صالح، round-trip حتمي.

### 1D — الجسر والحالة والسيناريوهات

- عقد sf-wasm typed وحالة مشروع داخل Worker، وإلغاء يمنع نشر ردود قديمة. لا كامل الجدول لكل render.
- مخزن مشروع واحد داخل الفرع المصادق عليه وأعلى remount الخاص بالتبويبات واللغة.
- What-If بمعاملات منفصلة، سيناريوهات متعددة ومقارنة وإعادة الأصل، وحفظ واستعادة إعداداتها.
- الملفات: sf-wasm، وحدات studio worker/store، طبقة التخزين المحلية وفق القرار المعتمد.
- الإثبات: تسابق طلبين، إلغاء، فشل عامل، حفظ/إعادة فتح بلا أسرار، لا تغییر المصدر بالسيناريو.

### 1E — مسار حي واحد عبر Views الأربعة

- SmartDropzone يمرر File حقيقيًا للمشروع بعد التحقق؛ لا ملخص XLSX ثابت.
- إضافة Views المرتبطة والمؤشر الحقيقي إلى Shell الحالي بعد البوابة فقط، دون ادعاء أن محررات Phase 3 مكتملة.
- VerifiedNumberChip يفتح تفاصيل تحقق من token الحقيقي، ومراجع الصفوف قابلة للوصول، والمقاييس القديمة غير معنونة verified.
- ICU translations وbrand/tokens وkeyboard/RTL/LTR والثيمين وتقليل الحركة.
- الإثبات: تعديل خلية وصيغة وسيناريو عبر المتصفح، تطابق الأربعة، نقرة وصول للأصل، تبويب/لغة لا يفقد المشروع، استيراد فارغ/تالف ومصدر كبير دون تجمد.

## 4. التحقق والتوقف

- اختبارات Rust المركزة ثم workspace، واختبارات Vitest وtypecheck/lint/build، ثم make check.
- متصفح حقيقي يختبر نجاح تدفق حساب محلي مخصص للاختبار دون تغيير التطبيق أو استخدام بيانات/خدمة الإنتاج.
- Benchmark بأحجام بيانات اصطناعية معلنة، مع فصل زمن الحساب عن الاستجابة وحالة stale؛ لا قياسات تقديرية.
- تقرير Phase 1 عند وجود تنفيذ فعلي: الأوامر والنتائج والقياسات والحدود والملفات وSHA وCI.
- لا Phase 2 إلا بعد تحقيق عقد قبول Phase 1 كاملًا. أي إخفاق أو حاجة لسياسة محمية توقف الجزء المتأثر وتُعرض على المالك.
