# خطة STUDIO-Phase-4

**الحالة:** لم يبدأ؛ يعتمد على نجاح Phase 3.  
**العقد:** [المهمة](../tasks/STUDIO-Phase-4.md).

## خطوات التنفيذ

1. وصف القوالب الخمسة كبيانات داخل نموذج Blocks/scenes الحالي؛ لا صور ثابتة أو حساب مستقل لكل قالب. الافتراضي boardroom-keynote.
2. ربط slots بمقاييس موجودة وفحص المتطلبات؛ لا خريطة بلا بيانات جغرافية صحيحة، ولا توقع غير مميز، ولا رقم بديل عند غياب المصدر.
3. تبديل القالب وتخصيصه وحفظ نسخة يستعمل نفس أوامر التحرير ويحفظ الأصل ومراجع المقاييس.
4. Capsule exporter يبني Snapshot ذرية للإصدار الحالي بعد اكتمال الحسابات والتحقق من المراجع؛ يرفض حالة غير صالحة بوضوح قبل كتابة الملف.
5. تضمين Dashboard/Slides/Report/resources/verification metadata، مع بيان وقت الإنشاء والإصدار وعدم المزامنة التلقائية مع المشروع الأصلي.
6. تضمين runtime محلي محدود للفلاتر والحسابات المطلوبة دون API/CDN. لا إعادة حساب اقتصادي حساس في JavaScript؛ تضمين WASM المحلي إذا كان التفاعل يحتاج حسابًا جديدًا.
7. توليد HTML/JSON/SVG حسب السياق الآمن، script/style ثابتان موثوقان وبصمات CSP؛ النصوص لا تدخل سياق تنفيذ. رفض أنواع/حجوم أصول خطرة، وعدم تضمين أسرار أو معلومات حساب.
8. تنزيل جديد فقط، مع احترام حدود الحجم والذاكرة وإتاحة المحتوى واللغتين.

## الملفات

وحدات templates وcapsule-exporter ضمن مساحة studio/تصدير حالية إن وجدت، ومشغل offline منفصل عن bootstrap التطبيق المصادق عليه دون جعله مدخلًا بديلًا لمساحة العمل. تعديل نموذج المشروع عند الحاجة فقط، مع serializers وi18n واختبارات التصدير؛ لا repurpose للـowner service worker أو تعديل سياسة الإنتاج.

## الإثبات

- تخصيص كل قالب وتبديله وحفظه ثم فتحه دون فقد روابط.
- فتح ملف `.safi.html` فعلي عبر file URL في Chromium مع الشبكة معطلة من السياق، ثم استخدام فلاتر/تنقل/رسوم وتدقيق كل metric مقابل المصدر.
- لا طلبات خارجية، وكل الخطوط/المكتبات لازمة موجودة محليًا.
- فحوص أسرار وsession fields، وإدخالات نصية محلية تحاول كسر HTML/JSON/SVG ولا تنفذ شيئًا.
- حالات stale/missing references/oversize/تلف manifest، واختبار Snapshot الواضح وعدم الكتابة إلى المشروع الأصلي.
- gates كاملة وتقرير القيود وSHA/CI قبل Phase 5، دون ادعاء ضمان مصدر البيانات لمجرد تطابق hash.
