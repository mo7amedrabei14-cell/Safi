# خطة تنفيذ المهمة `T1.09` — مخطط الوصفة والخطوات وبصمة المحتوى الحتمية (`crates/sf-recipe`)

## 1. الهدف والنطاق الحصري
تنفيذ المهمة **`T1.09` فقط** من الشريحة `S1` (القسم 19.7) لتوسيع حزمة **`crates/sf-recipe` حصريًا** بتمثيل مخطط الوصفة (Recipe Schema) وفق القسمين 4.9 و19.5، موفّراً:
1. **هياكل الوصفة والخطوات (`SafiRecipe`, `Step`, `ColumnRule`)**: مطابقة تامة لمخطط JSON المعتمد في القسم 19.5 (`schema_version = 1`, حقول `id`, `name`, `steps`, العمليات التسع المعتمدة في `op`).
2. **بصمة المحتوى الحتمية (`content_hash`)**: حساب بصمة محتوى الوصفة (`BLAKE3` أو تجزئة حتمية مستقرة مستقلة عن ترتيب المفاتيح والمسافات).
3. **الحتمية التامة**: ربط تنفيذ الخطوات بمحرك التنظيف بحيث يعطي نفس الملف ونفس الوصفة ناتجًا متطابقًا بايتًا ببايت (`AGENTS.md` Rule #12).
4. **اختبارات القبول والخصائص (`proptest`)**: إثبات سلامة التحويل من وإلى JSON، وثبات بصمة المحتوى، وتطابق مخرجات تطبيق الوصفة مرتين بايتًا ببايت.

### قيود النطاق الصارمة (Zero Scope Creep)
- النطاق محصور حصريًا داخل `crates/sf-recipe`.
- **لا يُبنى** ترحيل الإصدارات القديمة أو مطابقة تغير شكل الأعمدة المتقدمة (تخص `T2.01` و`T2.03`).
- **لا تبدأ** حزمة التقارير (`sf-report` تتبع المهمة `T1.10`).
- **صفر اعتماديات شبكة** داخل محرك Rust.

## 3. التصميم التفصيلي للمخرجات داخل `crates/sf-recipe`

### أ. الاعتماديات في `crates/sf-recipe/Cargo.toml`
- الاعتماد على `sf-core`, `sf-clean`, `serde`, `serde_json`, `blake3`.
- إضافة `proptest = "=1.5.0"` ضمن `[dev-dependencies]`.

### ب. وحدات الحزمة الجديدة (`crates/sf-recipe/src/lib.rs` و `recipe.rs`)
1. هيكل `SafiRecipe` ومجموعات الخطوات (`Step`) المدعومة بعمليات التنظيف التسع المعتمدة في القسم 19.5.
2. دالة حساب بصمة المحتوى (`content_hash`) الحتمية.
3. اختبارات الوحدات والخصائص للتحقق من تطابق البايتات وبصمة المحتوى.
