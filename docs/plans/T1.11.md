# خططة تنفيذ المهمة `T1.11` — حزمة جسر WebAssembly لمتصفح الويب (`crates/sf-wasm`)

---

## 1. الهدف والمخرجات المطلوبة
- بناء حزمة `crates/sf-wasm` لربط محركات Rust (`sf-core`, `sf-io`, `sf-arabic`, `sf-profile`, `sf-clean`, `sf-recipe`, `sf-report`) بـ JavaScript/TypeScript عبر `wasm-bindgen`.
- تصدير الدوال الأساسية: `analyze`, `suggest_steps`, `apply`, `undo`, `export_xlsx`, `report_html`.
- خطّاف ذعر (`panic hook`) مخصص يحوّل أي ذعر في Rust إلى خطأ معرف برمز `SF-UNK-001`.
- ضمان صفر اعتماديات شبكة (`AGENTS.md` Rule #7) والتوافق التام مع متطلبات الأمان والخصوصية (القسم 8).

---

## 2. خطوات التنفيذ
1. **إنشاء هيكل الحزمة (`crates/sf-wasm/Cargo.toml` و `src/lib.rs`)**:
   - إعداد التبعيات وتكوين `crate-type = ["cdylib", "rlib"]`.
   - إعداد التهيئة وتوجيه الأخطاء والذعر (`std::panic::set_hook`).
2. **تنفيذ الدوال المصدرة (Wasm Bindings)**:
   - `analyze_file(data: &[u8], filename: &str)`
   - `suggest_steps(profile_json: &str)`
   - `apply_recipe(data: &[u8], recipe_json: &str)`
   - `undo_recipe(...)`
   - `export_xlsx(...)`
   - `report_html(...)`
3. **الاختبار والتحقق**:
   - كتابة اختبارات الوحدات والتحقق من عدم وجود أي استدعاءات شبكية (`tools/check-no-network.sh`).

---

## 3. معايير القبول والتحقق
- تمرير `cargo check -p sf-wasm` و `cargo test -p sf-wasm`.
- اجتياز فحص الشبكة بـ `tools/check-no-network.sh`.
- توثيق القرار في `docs/DECISIONS.md`.
