# خطة تنفيذ المهمة T5.01 — غلاف Tauri 2.2 وقائمة السماح الصارمة (القسمان 8.6 و10.2)

- **معرّف المهمة**: `T5.01`
- **الفرع**: `task/T5.01`
- **المرجع الحاكم**: `docs/spec/19-handoff.md` §19.11 (سطر T5.01)، `docs/spec/08-security-privacy.md` §8.6، `docs/spec/10-apps-distribution.md` §10.2.
- **معيار القبول**: محتوى بعيد مرفوض، ورابط عميق بمعامل غير مسموح لا يُنفَّذ.

## 1. تصحيح النطاق

العمل السابق المُودَع باسم T5.01 كان وحدة `tauri_guard` داخل `sf-server` وغير معلنة في `lib.rs`، ولا يوجد تطبيق Tauri في المستودع. هذه الخطة تستبدله بغلاف حقيقي:

- `crates/sf-desktop`: قلب سياسة الأمان (Rust نقي، بلا شبكة، قابل للاختبار في CI).
- `apps/desktop/src-tauri`: تطبيق Tauri 2.2.0 فعلي بقائمة سماح وأوامر وروابط عميقة وارتباط ملفات.

## 2. البنية

### 2.1 `crates/sf-desktop` (عضو مساحة العمل، صفر شبكة)

| الملف | المسؤولية |
| --- | --- |
| `error.rs` | رموز `SF-SYS-002..011` (نطاق `SYS` المقفل في القسم 15.4) بلا نصوص واجهة مكررة (القاعدة 9). |
| `content.rs` | `validate_app_navigation`: يسمح بأصول التطبيق المحلية فقط (`tauri://localhost`, `http(s)://tauri.localhost`)، ويرفض `http(s)` البعيدة و`file:` و`data:` و`javascript:` وتجاوز المسارات. و`validate_external_link`: `https` فقط، بلا بيانات اعتماد ولا `localhost` ولا IP. |
| `deep_link.rs` | محلل `safi://` صارم: فعل من قائمة سماح (`open`, `settings`)، معاملات من قائمة سماح لكل فعل، معامل واحد فقط، فك ترميز نسبة صارم، مسار مطلق داخل مجلد الهدف بامتداد `csv/xls/xlsx`، ورفض `..` وUNC والفهارس والأحرف التحكمية. |
| `commands.rs` | قائمة سماح أوامر IPC الثلاثة (`app_info`, `pick_input_file`, `pick_output_file`) وحد 1 MiB لكل حمولة. |
| `capabilities.rs` | قائمة سماح أذونات Tauri صريحة: `core:default`, `dialog:allow-open`, `dialog:allow-save`, `deep-link:default` فقط؛ كل شيء آخر مرفوض. |
| `tests/shell_config.rs` | اختبار انحراف يقرأ `tauri.conf.json` و`capabilities/default.json` و`main.rs` ويتحقق: CSP صارم بلا `unsafe-inline/eval`، نافذة واحدة، ارتباط `csv/xls/xlsx`، مخطط `safi`، غياب أذونات `fs/shell/http/process/updater`، ووجود تهيئة النسخة الواحدة والرابط العميق. |

### 2.2 `apps/desktop/src-tauri` (Tauri 2.2.0 مثبَّت بدقة)

- `tauri.conf.json`: `frontendDist = ../../web/dist`، `devUrl = http://localhost:1420`، CSP صارم، `capabilities = ["default"]`، `devtools = false`.
- `capabilities/default.json`: النافذة `main` فقط والأذونات الأربعة أعلاه.
- `src/main.rs`: تهيئة `single-instance` و`deep-link` و`dialog`، `on_navigation` يمرّر كل عنوان إلى `content::validate_app_navigation`، وأمران لحوارات الملفات + `app_info`، وتمرير الرابط العميق المُتحقَّق إلى الواجهة كحدث `safi://deep-link`، و`windows_subsystem = "windows"` في الإنتاج.
- `bundle.active = false` مؤقتًا: المثبّتات والتوقيع والأيقونات هي مخرجات `T5.06`، فلا نضع أيقونات وهمية.

### 2.3 إصلاحات لازمة للبوابة

- إضافة `typescript` و`vite` و`@vitejs/plugin-react` كاعتماديات تطوير في `apps/web` لأن سكربت `build` يستدعيها ولا يستطيع الوصول إلى جذر المساحة.
- تثبيت منفذ Vite على `1420` ليتوافق مع `devUrl`.

## 3. الاختبارات

1. وحدة `content`: قبول الأصول المحلية الثلاثة، ورفض 10 حالات (بعيد، `file:`، `data:`، `javascript:`، `..`، `%2e%2e`، بايت NUL، شرطة مائلة عكسية، مسافة بادئة، طول زائد).
2. وحدة `deep_link`: قبول `open` مع مسار عربي مُرمَّز و`settings`، ورفض: مخطط خاطئ، فعل غير مسموح، معامل زائد/مكرر/فارغ، `..`، UNC، امتداد غير مدعوم، مسار نسبي، تجزئة، `@`، فك ترميز تالف.
3. وحدة `commands` و`capabilities`: كل أمر/إذن خارج القائمة مرفوض، والحد 1 MiB.
4. تكامل إعدادات: `tests/shell_config.rs` يمنع أي انحراف مستقبلي في ملفات Tauri.
5. `cargo check` لتطبيق Tauri نفسه على ويندوز + وظيفة CI `desktop-shell`.

## 4. البوابات والتسليم

- `cargo test -p sf-desktop` ثم `make check`.
- `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml`.
- تحديث `errors.toml` وتوليد الملفات، `CHANGELOG.md`، وتقرير `docs/reports/T5.01.md`.
- دفع الفرع وانتظار قبول المالك قبل الدمج؛ لا دمج تلقائي.
