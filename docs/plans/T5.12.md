# خطة تنفيذ المهمة T5.12 — الوصول إلى لوحة المالك خلف Zero Trust ومفتاح مادي مدمج (القسم 9.6، 9.8)

- **معرّف المهمة**: `T5.12`
- **الشريحة**: الشريحة S5: الديسكتوب والأوفلاين ولوحة المالك (القسم 19.11)
- **الفرع**: `task/T5.12`

## 1. الأهداف الرئيسية
1. **تطوير حارس `ZeroTrustGuard` في `crates/sf-server`**:
   - حماية مسارات لوحة المالك (`/v1/owner/*`) بترويسات Zero Trust إجبارية (`X-Safi-Zero-Trust-Token`, `X-Safi-Device-Attestation`).
   - فرض التحقق من التوقيع الرقمي للمفتاح المادي للأمان (`WebAuthn / FIDO2 / YubiKey Hardware Token`) لكل طلب إداري، مع التحقق من تفرد الـ `Nonce` والمهلة الزمنية الصارمة ($30$ دقيقة للجلسة).
2. **التحقق المزدوج للعمليات الحرجة**:
   - فرض إعادة المصادقة والتوقيع المشفر بمفتاح الأمان للعمليات الحرجة (وضع الصيانة الطارئ، نشر تحديث، تعديل أعلام الميزات).
3. **التدقيق والأمان وسجل التدقيق**:
   - تسجيل كافة محاولات الوصول (الناجحة والمرفوضة مع أسباب الرفض مثل `ZeroTrustHeaderMissing`, `InvalidHardwareTokenSignature`, `NonceReplayDetected`) في جدول وحقلي `audit_log` مقرونة ببصمات `BLAKE3`.
   - إصدار رموز الأخطاء المعيارية من `errors.toml` (مثل `SF-SEC-001`, `SF-SEC-002`, `SF-SEC-003`).
4. **الاختبارات والتكامل**:
   - كتابة اختبارات تكامل ووحدة شاملة في Rust تغطي كافة حالات القرف والقبول والتدقيق، والتحقق من عمل البوابة الكاملة عبر `make check`.
