# تدقيق معمارية Safi Quad-Studio

**التاريخ:** 2026-11-10  
**خط الأساس:** `119c3614235373628e7d00469dbb4b1ed685ef03` على `main`.  
**الحالة:** اكتمل التدقيق المحلي، ونجح `make check` برمز خروج 0. لا تعني هذه الوثيقة اكتمال الاستوديو أو تحقق CI/المتصفح. أكد المالك إبقاء بوابة التسجيل كما هي والبدء بالخطة؛ يبدأ العمل بإصلاحات صحة البيانات 1B، دون تجاوز التعارضات الخاصة ببناء المحرك والسياسات.

## 1. ما الذي أُنجز

- قُرئت تعليمات المشروع وقرارات المالك وسجل ADR والمواصفات ذات الأولوية، وفُحصت نقاط الدخول الفعلية والمحرك والتخزين والتصدير وCI.
- جرى التحقق المباشر من النتائج الحرجة في المصدر، وتشغيل اختبارات P0.05 المركزة وتجربة تخزين اصطناعية لا تستخدم بيانات عميل.
- لا كود استوديو جديد، ولا تغيير للمصادقة أو قاعدة البيانات أو الاشتراكات أو سياسات الأمان، ولا فرع جديد أو نشر إنتاجي.

## 2. الوضع المعماري عند خط الأساس

### الواجهة الفعلية

مسار المنتج هو `apps/web/src/main.tsx` ثم `App.tsx` ثم `ApplicationShell.tsx`. نقاط الدمج الصحيحة هي [ApplicationShell:34](../../apps/web/src/ApplicationShell.tsx#L34) و[SmartDropzone:83](../../apps/web/src/components/home/SmartDropzone.tsx#L83)، وليست صفحات Home/CleaningWorkspace القديمة أو `components/ChartStudio.tsx`.

- تحتوي الواجهة الحالية على Home وCleaning وRecipes وCharts وLibrary وOwner، لا الاستوديوهات الأربعة المطلوبة.
- يتحقق [قفل المصادقة:167](../../apps/web/src/ApplicationShell.tsx#L167) من وجود رمز غير فارغ، ويعود قبل تركيب مساحة العمل عند [السطر 229](../../apps/web/src/ApplicationShell.tsx#L229). يجب إبقاء هذا الترتيب.
- ينفذ `renderStudio` التنقل، ولا يمرر مشروعًا أو ملفًا مشتركًا. المفتاح `${activeTab}-${lang}` عند [السطر 262](../../apps/web/src/ApplicationShell.tsx#L262) يعيد تركيب المحتوى، ولذلك لا يصلح تخزين المشروع داخل حالة الاستوديو المنفردة.
- `SmartDropzone.onOpenCleaning` callback للتنقل فقط. الملف لا ينتقل معه إلى Cleaning؛ وملخص XLSX يحتوي أعدادًا ثابتة عند [السطر 161](../../apps/web/src/components/home/SmartDropzone.tsx#L161).
- لا توجد مطابقة لـ `.wasm` أو `new Worker` أو `wasm_bindgen` أو `sf-wasm` أو `sf_wasm` في `apps/web/src` عند التدقيق. لا يوجد جسر تنفيذ فعلي بين هذه الواجهة وRust.

### المحرك

[Cargo.toml:3](../../Cargo.toml#L3) يضم sf-core وsf-io وsf-arabic وsf-profile وsf-clean وsf-recipe وsf-report وsf-wasm، إضافة إلى server/desktop/cli. لا توجد sf-calc أو sf-detect.

- [Table:29](../../crates/sf-core/src/table.rs#L29) يخزن أعمدة داخل `Vec`، مع التحقق من استواء أطوالها. ليس Arrow أو Polars.
- [Value:115](../../crates/sf-core/src/value.rs#L115) يوفر أنواعًا تشمل Decimal والمال والنسب والمعرفات المحفوظة كنص؛ هذه قاعدة دلالية مفيدة.
- [CellValue:204](../../crates/sf-core/src/value.rs#L204) يفصل raw وnormalized وvalue وdisplay_mode، لكن بعض المستهلكين لا يحافظون على هذا الفصل.
- [SafiRecipe:72](../../crates/sf-recipe/src/recipe.rs#L72) نموذج وصفة خطي بإصدار وبصمة BLAKE3. ليس DataGraph، ولا يملك تعريف مؤشرات أو جدولة اعتمادات أو سيناريوهات.
- [sf-wasm:321](../../crates/sf-wasm/src/lib.rs#L321) يعرض دوال stateless، لا جلسة مشروع بإصدارات وحالة قابلة للتحرير.

### الفرق بين المواصفة والتنفيذ

[المواصفة 20.5:130](../spec/20-v5-architecture-upgrades.md#L130) تحسم Arrow/Polars وZustand وOPFS/wa-sqlite وGlide وTypst. اعتماديات [الويب:12](../../apps/web/package.json#L12) و[sf-core:10](../../crates/sf-core/Cargo.toml#L10) لا تطبق هذا المكدس. لا يجوز وصف `Table` أو جدول HTML أو `Map` بأنها تلك التقنيات.

هذا تعارض قائم، لا إذن باستبدال المعمارية المقفلة. لا يُبنى محرك حساب موازٍ في TypeScript لتغطية الفجوة.

## 5. مخاطر الأداء والذاكرة

- [CSV:24](../../crates/sf-io/src/reader_csv.rs#L24) يقرأ التدفق كاملًا قبل فحص الحجم؛ الاسم `read_csv_stream` لا يثبت البث المحدود بالذاكرة.
- يتضاعف التمثيل بين البايتات والنص والخلايا ونسخ الجداول؛ يجب قياس الذاكرة الفعلية، لا حجم الملف فقط.
- إزالة المكرر تحفظ نسخة الجدول كاملة في [cleaner:175](../../crates/sf-clean/src/cleaner.rs#L175)، بينما [المواصفة 4.10](../spec/04-engine.md#L124) تشترط فروقات لا نسخًا كاملة.
- حد Dropzone العملي 50 MiB، سقف WASM المسمى للذاكرة 128 MiB، ومواصفة الويب 250 MB/500 ألف صف؛ هذه حدود مختلفة لا تُوحد برفع رقم دون اختبار.
- [enforce_worker_sandbox:50](../../crates/sf-wasm/src/lib.rs#L50) يفحص معاملات فقط؛ المستدعون يمررون الزمن صفرًا. لا توجد مهلة تشغيل فعلية أو قياس لذاكرة العملية بذلك.
- لا دليل Benchmark جديد على 16ms أو استيعاب 500 ألف صف. زمن الاختبارات ليس زمن استيراد أو إعادة حساب.
- يلزم عامل خارج خيط الواجهة، صفحات بيانات للجدول، حدود للتعبيرات والمراجع وحجم المشروع، وإلغاء عمليات قديمة دون نشر نتائجها.

## 6. الحدود المقترحة بين Rust وWASM والواجهة

**هذا تصميم مقترح غير منفّذ، ويحتاج حسم تعارض المكدس أولًا.**

1. مصدر أصلي غير قابل للتعديل، ومعرفات ثابتة للمصدر والصفوف والأعمدة، وإصدارات أحادية الاتجاه للحالة المنشورة.
2. Rust يملك AST محدودًا للمعادلات، والتحويلات والأعمدة المحسوبة والمؤشرات والسيناريوهات، والتحقق من الأنواع والموارد قبل تنفيذ ذري.
3. DAG بمراجع صريحة وفحص دورات، وفهرس اعتمادات عكسي لإبطال المتأثر فقط. لا ترتبط الهوية باسم العمود المرئي أو بموضع صف قابل للتغير.
4. token يربط تعريف المعادلة وإصدارها والمصدر وإصداره وبصمة المدخلات والتحويلات والنتيجة ونوعها ووحدتها ومراجع الصفوف والأعمدة وإصدار المحرك وحالة التحقق.
5. BLAKE3 هو فحص اتساق، لا توقيع ثقة أو إثبات أن البيانات الأصلية صحيحة. لا مفاتيح توقيع جديدة ولا إعادة استخدام مفاتيح الأجهزة أو التراخيص.
6. وقت الحساب بيانات وصفية خارج هوية المحتوى الحتمي؛ إعادة الحساب للمدخلات ذاتها تعطي القيمة وبصمة المحتوى ذاتهما. تغير المصدر/الصيغة يبطل صلاحية token القديم، حتى إذا ظلت القيمة العددية مساوية.
7. جسر عامل typed: `requestId` و`projectId` و`expectedRevision` وأمر محدود؛ الرد يحمل الإصدار المقبول والنتائج المتأثرة أو رمز SF مسجل. تُرفض الردود المتأخرة، وتعرض المشاهدات stale أثناء إعادة الحساب.
8. الأرقام العشرية الكبيرة تعبر إلى JavaScript كنص عشري مضبوط، لا `Number` يفقد الدقة. الواجهة تنسق وتعرض وتربط؛ لا تعيد حساب SUM/AVG وغيرها.
9. الأربع Views تقرأ المؤشر نفسه. في Phase 1 يكفي إثبات المشاهدات المرتبطة الحقيقية؛ محرراتها الكاملة في Phase 3، دون ادعاء اكتمالها مبكرًا.
10. What-If طبقة معاملات لا تعدّل المصدر، محفوظة مع المشروع، والحساب داخل Rust.

**موضع الملكية:** لا يجوز أن يعتمد sf-core على sf-clean لأن الأخير يعتمد عليه أصلًا. يمكن وضع أنواع المصدر/token في sf-core، والتنسيق وتنفيذ التحويلات في sf-recipe الذي [يعتمد بالفعل على sf-clean:12](../../crates/sf-recipe/Cargo.toml#L12). إذا تطلب التصميم sf-calc، يجب حسم شرط الحوكمة المذكور في القسم 10 بدل الالتفاف عليه.

## 7. إدارة الحالة والحفظ والاستعادة

### الواقع

[EncryptedOPFSStorage:72](../../apps/web/src/storage/opfs-storage.ts#L72) يخزن في `Map` فقط. تجربة مستقلة باستخدام بيانات اصطناعية نجحت في القراءة من الكائن نفسه وفشلت عند إنشاء كائن جديد؛ لذلك لا توجد استدامة بين الجلسات.

يوجد AES-GCM/PBKDF2 فعلي عند توفر WebCrypto، لكن [المسار البديل:84](../../apps/web/src/storage/opfs-storage.ts#L84) يحوّل كلمة السر والبيانات إلى Base64. لا يجوز وصفه كتشفير أو نقله إلى مخزن المشروع.

### المقترح

- مخزن مشروع واحد فوق دورة حياة Views وتبديل اللغة، داخل فرع التطبيق المصادق عليه. لا تكرار لحالة المؤشرات في كل مكوّن.
- Zustand v5 وفق القرار القائم، مع بقاء الحساب ومؤشرات الصلاحية المرجعية في Rust.
- OPFS/wa-sqlite فعلي للمشروع، بمخطط محلي إصـداري منفصل تمامًا عن PostgreSQL وحسابات المستخدمين.
- حفظ الأصول الأصلية والتحويلات والسيناريوهات وإعدادات الرسوم والشرائح والمستندات والتخطيطات ومراجع المقاييس معًا.
- كتابة حالة جديدة والتحقق منها قبل تبديل المرجع النشط؛ فشل الحصة أو الانقطاع لا يستبدل نسخة سليمة بنصف مشروع.
- الاستعادة تتحقق من الحجم والإصدار والبصمات والمراجع، ثم يعيد Rust الحساب قبل عرض verified. لا استعادة لرموز جلسات أو بيانات حساب.
- نموذج Blocks/Scene منظم، لا DOM أو `contentEditable` وحده. undo/redo للمستند والتخطيط منفصل عن تاريخ تحويل المصدر مع معاملات واضحة.

## 8. المصادقة والصلاحيات والسياسات المحمية

- [auth-api:117](../../apps/web/src/lib/auth-api.ts#L117) يرسل Bearer عند الحاجة، مع no-store وcredentials omit ورفض redirects. يبقى كما هو.
- قرار [ADR-0012:168](../DECISIONS.md#L168) يحمي P0.05، ويصرّح أن تسجيل الدخول ليس استحقاق اشتراك. لا تُخترع صلاحية استوديو مدفوعة بناءً على البريد أو config محلي.
- يلزم حسم عقد الاستحقاقات قبل Phase 5 إذا كانت هناك قيود جديدة؛ بناء P0.06 أو تغيير الخادم ليس ضمن هذا التكليف.
- يمرر Shell حالة owner للـdock، لكنه لا يمرر بريد المشاهد إلى OwnerDashboard عند `renderStudio`. هذه ملاحظة مراجعة قائمة، وليست إثباتًا لتجاوز خادم أو إذنًا بتعديل RBAC. لا تستخدمها كمصدر لصلاحيات المشروع الجديد.
- [ترويسات الويب:8](../../apps/web/public/_headers#L8) تحتوي `style-src 'self' 'unsafe-inline'` رغم اشتراط الحظر في AGENTS والمهارة الأمنية. لا يجوز إعلان Strict CSP ناجح أو تعديل سياسة محمية بصمت.
- تعارض AES-GCM المعتمد في ADR-0006 مع قائمة التشفير المقفلة لا يحسم بكتابة خوارزمية بديلة. إعادة استخدام التشفير أو تغييره يحتاج قرارًا محددًا؛ لا تغيير الآن.

## 9. التصدير المستقل المقترح

الكبسولة `.safi.html` Snapshot محلي صريح، تضم Dashboard وSlides وReport والتصفية والرسوم ونسخة البيانات ومراجع المؤشرات وبصماتها ووقت الإنشاء، لا جلسة الحساب ولا أسراره.

- النصوص بيانات فقط، مع serialization يراعي سياق HTML/SVG/JSON ولا يفسرها ككود.
- تضمين الموارد محليًا دون CDN/API/خطوط خارجية، وبـCSP مقيد دون unsafe-inline/eval؛ تعتمد السكربتات الثابتة على hash مناسب عند التصميم.
- لا يحسب JavaScript مؤشرات مالية بديلة عن Rust. إذا تغيرت مؤشرات بسبب الفلاتر، يجب أن تحمل الكبسولة محرك الحساب المحلي اللازم أو نتائج مرتبطة محددة تغطي التصفية فعليًا؛ لا تدّعي التفاعلية من إخفاء أرقام ثابتة فقط.
- لا تدعي أن البيانات حية أو أن تعديل الكبسولة يعود تلقائيًا إلى المشروع.
- يلزم اختبار ملف `file://` مع شبكة معطلة، ودقة النتائج، ونصوص اختبار هجومية غير تنفيذية، وغياب الرموز، وحدود الحجم والذاكرة.

## 11. خطة الاختبارات وبوابات المراحل

| البوابة | الدليل المطلوب |
| --- | --- |
| الأساس/P0.05 | full gate، دخول مقفل وEscape/backdrop وإعادة تحميل، هوية جهاز مستقرة، عدم تركيب استوديو بلا مصادقة |
| Phase 1 | تعديل خلية/معادلة يبطل tokens التابعة فقط؛ ثبات المؤشرات غير التابعة؛ اتفاق Views الأربعة؛ إعادة حساب مطابقة؛ كشف قيمة معروضة محرفة؛ تتبع الصفوف؛ Undo/Redo يحفظ الأصل؛ قياسات UI على أحجام متعددة |
| Phase 2 | عربي/إنجليزي إلى DSL فعلي، رفض العمليات والمراجع والأنواع والموارد المخالفة ذريًا؛ منع AI من إنشاء token أو قيمة؛ تحديث narrative؛ تصحيح الشذوذ بموافقة وتراجع |
| Phase 3 | تحرير الجدول والمخطط والشرائح والـBlocks؛ تصفية مرتبطة؛ بناء يدوي بلا AI/قالب؛ حفظ وإعادة فتح حقيقيان عبر OPFS؛ استعادة المراجع والأصول والتاريخ |

الاختبارات تستخدم بيانات اصطناعية محلية فقط. اختبار native لـsf-wasm ليس اختبار تشغيل WASM داخل المتصفح. اختبارات SSR لا تثبت نجاح تسجيل دخول فعلي أو دورة مشروع.

### الأدلة المشغلة في هذه الجلسة

- `git status --short --branch`: نظيف على main عند البداية، وorigin/main يشير إلى نفس SHA المحلي. لم يُنفذ fetch، فلا يُدّعى التحقق من حداثة المرجع البعيد.
- `pnpm exec vitest run apps/web/src/ApplicationShell.test.tsx apps/web/src/App.shell.test.tsx apps/web/src/components/auth/AuthModal.test.tsx apps/web/src/components/layout/AccountAccessSheet.test.tsx`: **17/17 ناجحة، 4 ملفات، 8.28 ثانية**. هذه مدة suite وليست Benchmark للاستوديو.
- تجربة `EncryptedOPFSStorage` من Node: **تأكد فقد السجل عند إنشاء كائن جديد**، مع نجاح القراءة من الكائن الأول.
- `make check`: **نجح على المصدر غير المعدل، exit code 0**؛ شمل no-network والأخطاء والتباين وi18n وفحص migrations الساكن والتنسيق وClippy وtypecheck وlint وRust/Vitest والبناء وCodeburn والفحص الأمني وpnpm audit. لا يعني هذا تشغيل PostgreSQL فعلي أو Strix أو اختبارات المتصفح.
- بدأ Vite محليًا على `127.0.0.1:4186`. HTTP للصفحة ومدخل main.tsx أعاد 200. انتهت مهلة التنقل أولًا مع React root فارغ؛ ظهرت لوحة Sign in في مشاهدة لاحقة. لم يتغير التطبيق لمعالجة ذلك، ولم يُثبت سبب التأخر أو نجاح تسجيل دخول فعلي.
- `gh run list --branch main --limit 8`: لم يعمل لأن gh غير موجود. رابط CI في [تقرير P0.05 السابق](P0.05.md#L57) تاريخي، ولم تُتحقق حالته البعيدة في هذه الجلسة.

**بيئة الأوامر المقاسة:** Windows x64/Git Bash؛ Node v22.23.2، pnpm 10.8.1، cargo 1.99.1، rustc 1.99.1. هذه هي القيم التي أعادتها الأوامر الفعلية؛ ليست نسخة Node المذكورة في وصف جلسة الأداة.

### حدود البوابات الحالية

- [ci.yml](../../.github/workflows/ci.yml) يحتوي full gate لـWindows/Ubuntu وPostgreSQL وChromium وTauri. توجد اختبارات متصفح حقيقية في `tools/verify-intro-visual.mjs` و`tools/verify-device-identity.mjs`؛ غياب script اسمه e2e من package.json لا يعني غيابها.
- [Codeburn:7](../../tools/codeburn/burn.sh#L7) يعيد تشغيل cargo test ويتحقق من ملف إعداد؛ ليس قياسًا فعليًا لـcargo-mutants أو ميزانية توكنز.
- `verify-security.py` فاحص تثبيت اعتماديات/نطاق/ملفات؛ نجاحه وحده لا يثبت تشغيل Strix أو تدقيق CSP ديناميكيًا.
- [format-repair-once.yml](../../.github/workflows/format-repair-once.yml) يعمل على كل push إلى main وقد يكتب commit تنسيق. لم يُعدل. يجب إعادة فحص SHA البعيد بعد أي push مصرح به، ولا استخدام force أو إعادة كتابة التاريخ.

## 12. الملفات المتوقع تعديلها

المسارات الجديدة التالية مقترحة لا ملفات كود تم إنشاؤها:

- `crates/sf-core/src/datagraph.rs` لأنواع الهوية/token إن أثبتت حدود الملكية ذلك؛ `crates/sf-recipe/src/datagraph.rs` لتنسيق التحويلات داخل الاتجاه الحالي للاعتماد.
- وحدات sf-io/sf-clean المتأثرة فقط باختبارات حفظ الأصل والاستيراد الصحيح، ثم sf-wasm للعقد الفعلي مع العامل.
- `apps/web/src/ApplicationShell.tsx`: حقن مشروع بعد بوابة المصادقة فقط، دون إعادة تصميم الغلاف أو تغيير تدفقات الحساب.
- SmartDropzone وCleaningStudio وChartsStudio لتمرير الملف الحقيقي واستهلاك المشروع بدل العينات.
- وحدات جديدة خاصة بالاستوديو للعامل/المخزن/VerifiedNumberChip/Slides/Document/Free-Form/DSL/Capsule حيث لا يوجد تنفيذ قابل لإعادة الاستخدام.
- التخزين المحلي الحالي أو حد مشترك مطابق لـOPFS؛ ملفات i18n الرسمية، اختبارات Rust/Vitest/المتصفح، وملفات الاعتماديات/القفل فقط بعد الحسم.
- مهام وخطط STUDIO-Phase-1 إلى STUDIO-Phase-5، وتقارير المراحل عند وجود تنفيذ فعلي، وADR عند اعتماد قرار لا قبله.

## 13. ملفات وأنظمة لا تُلمس

- `crates/sf-server/**` و`server/migrations/**` وخدمات وقواعد الإنتاج.
- AuthModal وAccountAccessSheet وPasswordResetModal وdevice-identity وauth-api: تبقى عقودها وسياساتها بلا تغيير ضمن الاستوديو.
- config/business.json ولوحة المالك وآليات الخطط والتسعير وRBAC والجلسات والتراخيص.
- الموقع التسويقي وTauri capabilities وسياسات CSP وملفات CI، دون تصريح خاص عند التعارض.
- مخرجات generated وdist وtarget وnode_modules؛ لا تعديل يدويًا لتصنيع نجاح.
- لا مفاتيح أو tokens أو ملفات بيانات مستخدم في المشروع الجديد أو التقارير أو السجلات أو الكبسولة.
