# تقرير إنجاز المهمة T4.02 — ترحيلات PostgreSQL 18 ومصادقة مفاتيح API وجلسات Valkey عالية الأداء

- **المعرّف**: `T4.02` — الشريحة S4 (القسم 9.2، 9.3)
- **الفرع**: `task/T4.02`
- **التاريخ**: 2026-11-06

## ما الذي أُنجز

1. **ترحيل قاعدة بيانات كامل**: ملف صاعد وهابط (`crates/sf-server/migrations/0001_s4_core.*.sql`) ينشئ `users` و`workspaces` و`memberships` و`api_keys` و`sessions` و`audit_log` بمعرّفات `uuidv7()` المدمجة، وعمود مولَّد Virtual، وRLS مفروض على كل جدول يحمل `workspace_id`، وتقسيم شهري لـ`audit_log` يُفعَّل عبر `pg_partman` فقط عند توفره، بلا أي اعتماد على Supabase.
2. **طبقة مصادقة مفاتيح API**: صيغة `sfk_live_<prefix>_<secret>`، تخزين بصمة BLAKE3 فقط، تحقق ثابت الزمن، فحص الانتهاء والإبطال، ونطاقات `read/write/admin` تُفرض على كل مسار في Axum 0.8.
3. **إدارة جلسات عبر Valkey 8**: رمز `sfs_*` يُخزَّن في PostgreSQL كبصمة فقط، وتُخدم القراءة الساخنة من Valkey بنمط cache-aside مع TTL متجدد، والإبطال يحذف المفتاح فورًا ثم يعلّم الصف في القاعدة، مع بقاء القاعدة مصدر الحقيقة عند تعطل الكاش.
4. **واجهات وربط**: `/health` عام، و`/v1/auth/whoami` يقبل مفتاحًا أو جلسة، و`/v1/auth/sessions` (إنشاء)، و`/v1/auth/sessions/current` (قراءة وحذف)، وكل رد يحمل `X-Request-ID`، والأخطاء `problem+json` برموز `SF-AUTH-001` إلى `SF-AUTH-006`.
5. **الاختبارات**: 24 اختبار Rust (وحدة + تكامل عبر الموجّه الحقيقي) تغطي التوليد والتحقق والانتهاء والإبطال والنطاقات وتخزين الكاش ودورة الجلسة الكاملة، إضافة إلى فاحص ترحيلات ثابت مع اختبار ذاتي سلبي داخل `make check`.

## كيف تجرّبه بنفسك

1. شغّل اختبارات الخادم: `cargo test -p sf-server` — يجب أن ترى 24 اختبارًا ناجحًا.
2. شغّل فاحص الترحيلات: `py -3 tools/verify-migrations.py` ثم `py -3 tools/verify-migrations.py --self-test`.
3. لتجربة الترحيل على قاعدة حقيقية (مطلوب PostgreSQL 18 و`psql`): أنشئ قاعدة مؤقتة ثم `SF_TEST_DATABASE_URL=postgres://... bash tools/test-migrations.sh`.
4. شغّل البوابة كاملة: `make check`.

## ما الذي فشل أو لم يكتمل

- **اختبار الترحيل الحقيقي صاعد/هابط لم يُشغَّل محليًا** لأن جهاز التنفيذ لا يحتوي PostgreSQL ولا `psql` ولا Docker. الفحص المنجز هو فحص ثابت للملفات (أزواج، حذف الهابط، RLS، `uuidv7`، غياب SERIAL) وليس إثباتًا على قاعدة حية. السكربت الجاهز للتحقق الحي هو `tools/test-migrations.sh` وينتظر قاعدة مؤقتة.
- **Valkey لم يُشغَّل حيًا** لنفس السبب؛ منطق الكاش مُثبت عبر تنفيذ ذاكري مطابق للواجهة، وتنفيذ Valkey مبني ومفحوص نوعيًا لكنه لم يتصل بخادم فعلي.
- اختبار العزل بين مساحتين مكتوب داخل `tools/test-migrations.sh` ولم يُنفَّذ بعد؛ لا أعلن نجاحه قبل تشغيله.
- تأجيل تكامل PgBouncer و`sqlx migrate` إلى بيئة النشر: الترحيلات موجودة وجاهزة، لكن لم تُضف طبقة تشغيل تلقائي في الخادم بعد.

## قرارات أحتاجها منك

1. هل أوافق على تثبيت PostgreSQL 18 وValkey 8 محليًا (أو عبر Docker) لتشغيل اختبار الترحيل الحي وإثبات العزل قبل القبول؟
2. هل تريد أن يبدأ الخادم تلقائيًا بتشغيل الترحيلات عند الإقلاع (`sqlx::migrate!`) أم تبقى خطوة نشر منفصلة مع PgBouncer؟
3. هل أضمّن مسارات إدارة مفاتيح API (إنشاء/سرد/إبطال) في `T4.03` أم داخل هذه المهمة قبل القبول؟
