## 9. الخلفية والحسابات والفوترة ولوحة المالك

الخادم صغير عمدًا: يدير الحسابات والاشتراكات والمزامنة المشفّرة والتحديثات، ولا يملك مفاتيح فتح أي ملف لأي عميل.

### 9.1 الخدمات (وحدات الخادم)

 1. **الهوية (Auth):** تسجيل ودخول وPasskeys وجلسات وMFA.

 2. **الحسابات ومساحات العمل:** الأعضاء والأدوار والدعوات.

 3. **الفوترة:** الخطط والاشتراكات والفواتير وWebhooks المدفوعات.

 4. **التراخيص:** إصدار وتجديد رموز التراخيص الموقّعة.

 5. **المزامنة:** تخزين كتل مشفّرة (`ciphertext`) مع الإصدارات، بلا فهم لمحتواها.

 6. وسيط **الذكاء الاصطناعي:** يخفي المفتاح، ويطبّق ضغط السياق عبر **Headroom** والتوجيه عبر **Smart Task Router**، ويطبّق الحصص، ويسجّل البيانات الوصفية فقط.

 7. **مشاركة التقارير:** روابط مشفّرة، ومفتاح فك التشفير في جزء الرابط بعد `#` فلا يصل الخادم.

 8. **التحديثات:** بيانات الإصدارات والتوقيعات والنشر التدريجي.

 9. **الدعم:** التذاكر وحزم التشخيص.

10. **الإدارة والتدقيق:** واجهة المالك وسجل التدقيق.

11. **المفاتيح وWebhooks:** مفاتيح API (تُخزَّن مجزَّأة `hash` فقط) وإشعارات المهام.

### 9.2 قاعدة البيانات

**PostgreSQL 18 الأصلي (صفر Supabase نهائيًا)**، ومعرّفات UUID v7 المدمجة أصليًا في النواة عبر دالة `uuidv7()`، ونظام الإدخال/الإخراج غير المتزامن `Async I/O` (`io_uring`)، والأعمدة المولدة افتراضيًا `Virtual Generated Columns`، وفهارس `B-Tree Skip Scan`، وعزل صفوف مساحات العمل بـ `Row-Level Security` الأصلي مع `PgBouncer` و`pg_partman`، وترحيلات مرقَّمة مفحوصة وقت الترجمة عبر `SQLx 0.8` ولا تعديل يدوي. حذف بيانات المستخدم عند الطلب حذف فعلي، ما عدا سجلات الفوترة التي يوجبها القانون.

| الجدول | ما يحمله | 
| ----- | ----- | 
| `users`، `credentials` | الحساب وبيانات Passkeys ومفاتيح التحقق | 
| `sessions`، `devices` | الجلسات والأجهزة وآخر نشاط | 
| `workspaces`، `memberships`، `invitations` | المساحات والأعضاء والدعوات والأدوار | 
| `plans`، `entitlements`، `subscriptions`، `invoices` | الخطط والحقوق والاشتراكات والفواتير | 
| `licenses` | الرموز الصادرة وربطها بالأجهزة | 
| `sync_objects` | كتل مشفّرة: المعرّف والإصدار والحجم فقط | 
| `share_links` | معرّف الرابط وانتهاؤه وعدد مرات الفتح، بلا مفتاح | 
| `api_keys`، `webhooks` | مجزَّأة ومحدَّدة النطاق | 
| `ai_requests` | عدد ومدة وتكلفة ونسبة ضغط التوكنز، بلا محتوى | 
| `consent_records` | ما وافق عليه المستخدم ومتى | 
| `audit_log` | سجل متسلسل بالبصمات (`hash chain`) لا يقبل التعديل | 
| `feature_flags`، `releases` | الأعلام والإصدارات ونسب النشر | 
| `support_tickets` | التذاكر وحزم التشخيص | 

### 9.3 الواجهة البرمجية

* REST موثّقة بـ OpenAPI 3.1 تحت `/v1`، والأخطاء بصيغة `problem+json` (RFC 9457).

* ترقيم بمؤشر (`cursor`)، ومفاتيح `idempotency` لكل عملية مالية.

* كل نقطة تفحص الملكية والصلاحية ومعها اختبار يثبت رفض الوصول غير المصرَّح.

* حدود معدل وحصص لكل مستخدم ومفتاح وعنوان IP.

* أهداف الأداء: $p_{95} < 300\text{ ms}$ للقراءة، وتوفر $99.9\%$ هدفًا.

### 9.4 الخطط والتراخيص

| الخطة | الحدود الأساسية (فرضيات تُختبر) | 
| ----- | ----- | 
| مجانية | ملفات صغيرة، $3$ عمليات شهريًا، شارة «نُظِّف بـ صافي»، بلا ذكاء اصطناعي سحابي (يسمح بـ WebLLM المحلي) | 
| احترافية | ملفات كبيرة، عمليات غير محدودة، الوصفات والذاكرة، حصة ذكاء اصطناعي، تقارير بلا شارة ($350\text{ ج.م}$ شهريًا أو $3,000\text{ ج.م}$ سنويًا بمصر / $99\$$ سنويًا عالميًا) | 
| فريق | كل ما سبق + مساحات مشتركة وصلاحيات وموافقات وسجل نشاط | 
| مؤسسات | أوفلاين كامل، SSO وSCIM، إخفاء بيانات متقدم، DPA، دعم مخصص، سعر بالتفاوض | 

* **ترخيص الديسكتوب:** رمز موقّع بـ `Ed25519` يحمل الخطة وتاريخ الانتهاء وبصمة الجهاز، ويتجدد بصمت عند الاتصال. مهلة السماح بلا إنترنت $30$ يومًا قابلة للضبط (وسنوية للمؤسسات وفق ن11)، ثم يعود التطبيق للخطة المجانية دون فقد أي بيانات.

* لا تقوم الحماية من النسخ غير المرخَّص على إخفاء الكود، بل على تحقق الرمز وتحديثات الميزات المرتبطة بالحساب.

### 9.5 الفوترة

* **المدفوعات:** Paymob للسوق المحلي المصري (جنيه مصري) وLemon Squeezy كتاجر مسجَّل عالمي (MoR).

* التحقق من توقيع كل Webhook، ومعالجة العمليات المكررة بأمان.

* إعادة محاولة الدفع الفاشل (`dunning`) مع رسائل بريد واضحة، ثم تخفيض تدريجي للخطة لا قطع مفاجئ.

* فترة تجربة بلا بطاقة، وكوبونات، وخصم سنوي، وحساب تناسبي (`proration`) عند الترقية.

* فواتير PDF بالعربية والإنجليزية. الضرائب بحسب قوانين كل دولة: استشر محاسبًا قانونيًا.

### 9.6 لوحة المالك (Owner Console)

الوصول: نطاق منفصل خلف Zero Trust، مع Passkey على مفتاح أمان مادي إلزامي، وفحص حالة الجهاز، وجلسة $30$ دقيقة، وإعادة مصادقة قبل أي إجراء مدمّر، وتسجيل كل نقرة في سجل التدقيق.

| الوحدة | ما تتحكم فيه | 
| ----- | ----- | 
| اللوحة الرئيسية | المستخدمون النشطون، الإيراد الشهري، معدل الإلغاء، الأجهزة، الأخطاء | 
| المستخدمون | البحث، حالة الحساب، تعليق وتفعيل، إعادة تعيين الدخول، بيانات وصفية فقط | 
| الاشتراكات والفوترة | تغيير خطة، منح أشهر، استرداد، كوبونات، فواتير | 
| الخطط والحقوق | محرر الحدود والميزات لكل خطة بلا نشر كود | 
| الإصدارات | نشر إصدار، نسبة تدريجية، إيقاف فوري لأي إصدار معيب، ملاحظات الإصدار | 
| أعلام الميزات | تفعيل ميزة لمستخدم أو خطة أو نسبة | 
| الدعم | صندوق التذاكر، حزم التشخيص، ردود جاهزة | 
| المحتوى | القوالب، مركز المساعدة، المدونة، النصوص القانونية بنسخها | 
| الذكاء الاصطناعي | الاستهلاك والتكلفة وحدود لكل مستخدم وإيقاف طارئ | 
| مركز الأمان | شذوذ الدخول، عناوين محجوبة، مفاتيح API، عارض سجل التدقيق | 
| صحة النظام | الطوابير وقاعدة البيانات والأخطاء ومؤشرات الأداء | 
| طلبات البيانات | سير عمل تصدير وحذف بيانات المستخدمين | 

* **قرار تصميمي مهم:** المالك يتحكم في كل شيء عن الخدمة، ما عدا قراءة محتوى ملفات العملاء ووصفاتهم، لأنها مشفّرة بمفاتيح لا يملكها الخادم. وهذا ليس نقصًا بل ميزة بيع للجهات الحساسة، ويحميك قانونيًا من مسؤولية بيانات لا تحتاجها.

* ممنوع «انتحال شخصية المستخدم» (`impersonation`). البديل: «عرض واجهة المستخدم» بحالته الوصفية بلا محتوى.

* حساب الطوارئ (`break-glass`): مفتاح أمان مادي ثانٍ في مكان آمن، واستخدامه يطلق تنبيهًا فوريًا.

* يمكن تفعيل «موافقة شخصين» على الإجراءات الخطرة حين يوجد مشرف ثانٍ.

### 9.7 المراقبة والتشغيل

* OpenTelemetry للمقاييس والسجلات والتتبع بلا بيانات شخصية.

* فحوص توفر خارجية، وصفحة حالة عامة، وتنبيهات على هاتف المالك.

* أهداف مستوى الخدمة (SLO): توفر $99.9\%$، و$p_{95} < 300\text{ ms}$، ومعدل أخطاء أقل من $0.5\%$.

* نشر تدريجي (`canary`) مع تراجع آلي عند ارتفاع الأخطاء.

### 9.8 مركز التحديثات والتحكم الكامل عن بُعد

من حساب المالك وحده تنشر تحديثًا لكل النسخ المثبّتة وتتحكم في كل شيء عن الخدمة، بواجهة بسيطة من ست بطاقات وخطوات لا تزيد عن ثلاث. البساطة هنا شرط قبول، وليست تجميلًا.

#### أولًا: الوضع البسيط (الافتراضي — بنمط `I-Have-ADHD`)

الشاشة الرئيسية: شريط حالة بثلاثة ألوان (أخضر «كل شيء سليم»، أصفر «يحتاج انتباهك»، أحمر «مشكلة الآن»)، وتحته ست بطاقات كبيرة:

1. انشر تحديثًا

2. أرسل رسالة للمستخدمين

3. المستخدمون والاشتراكات

4. شغّل أو أوقف ميزة

5. الدعم

6. الأمان والحالة

* بحث شامل (`Ctrl` أو `Cmd + K`) ينفّذ أي إجراء بالكلمات، مثل «أوقف الذكاء الاصطناعي» أو «ابحث عن مستخدم».

* كل معالج لا يزيد عن $3$ خطوات، بقيم افتراضية آمنة، وبعربية بسيطة بلا مصطلحات تقنية.

* «الوضع المتقدم» يكشف كل التفاصيل والفلاتر لمن يريدها.

* نسخة PWA للمالك على الموبايل للطوارئ مع إشعارات فورية.

* كل إجراء خطر يتطلب كتابة كلمة التأكيد ثم لمس مفتاح الأمان، ولكل إجراء زر تراجع حيث أمكن.

#### ثانيًا: معالج «انشر تحديثًا» ($3$ خطوات)

| الخطوة | ما تفعله | الافتراضي الآمن | 
| ----- | ----- | ----- | 
| 1\. اختر الإصدار | يظهر آخر إصدار اجتاز كل بوابات CI. ملاحظات الإصدار تُكتب بالعربية بمساعدة الذكاء الاصطناعي وتُترجم لكل لغات الواجهة وتراجعها أنت | لا يظهر إلا إصدار اجتاز كل البوابات | 
| 2\. لمن ولماذا | الجميع أو شريحة (المنصة، الإصدار الحالي، اللغة، الدولة، الخطة، مساحة العمل). النوع: اختياري أو موصى به أو إجباري (لثغرة أمنية أو خلل خطير) | اختياري ونشر تدريجي | 
| 3\. راجع ووافق | ملخص من سطر واحد، ثم لمس مفتاح الأمان | موافقة بمفتاح الأمان | 

بعد الموافقة ينتشر التحديث تدريجيًا ($1\%$ ثم $5\%$ ثم $25\%$ ثم $100\%$ بفواصل زمنية). يتوقف تلقائيًا إن ارتفع معدل الأعطال فوق حد مضبوط. وتشاهد شريط تقدم مباشرًا (كم نسخة حُدِّثت وكم فشلت) مع زرّي «أوقف» و«تراجع».

#### ثالثًا: كيف تستقبل كل منصة التحديث

| المنصة | الطريقة | الإجباري | 
| ----- | ----- | ----- | 
| الويب | يصل فور النشر عبر Service Worker، مع شريط «تحديث متاح» أو تحديث تلقائي عند الفتح التالي | ممكن | 
| ويندوز ولينكس | يفحص التطبيق عند التشغيل وكل $6$ ساعات تقريبًا بتأخير عشوائي، وينزّل في الخلفية بعد التحقق من التوقيع، ويثبّت عند الإغلاق أو بنقرة. لا يقاطع مهمة جارية أبدًا | ممكن: شاشة «تحديث مطلوب» لطيفة تنتظر انتهاء المهمة الجارية | 
| أندرويد وآيفون | عبر المتجر فقط (قواعد المتاجر تمنع تحديث الكود الأصلي من خارجها). «الحد الأدنى للإصدار» يعرض شاشة «يرجى التحديث» برابط المتجر | الحد الأدنى فقط | 
| المؤسسات | العميل يثبّت قناة التحديث أو يوقفها بسياسة | لا يتجاوز المالك سياسة العميل إلا بطلب صريح منه | 

* **حماية التحديث:** التحقق من التوقيع، ومنع الرجوع لإصدار أقدم (الرقم يزيد دائمًا). «التراجع» ينشر إصدارًا جديدًا برقم أعلى بكود قديم، فلا يستطيع مهاجم إعادة نسخة بها ثغرة.

* **كفاءة:** تحديثات فروقات (`delta`) لتقليل الحجم، واستئناف التنزيل المقطوع، واحترام الإنترنت الضعيف.

* **أمان الإقلاع:** يحتفظ التطبيق بالنسخة السابقة، فإن فشل الإقلاع بعد التحديث عاد إليها تلقائيًا وأبلغ المالك.

* **ما يصل بلا متجر على كل المنصات:** حزم اللغة والقواعد والقوالب والإعدادات (البيانات الموقَّعة) تُحدَّث لاسلكيًا، فيمكنك تحسين التنضيف للأندرويد والآيفون دون انتظار المتجر.

#### رابعًا: الإعدادات والرسائل عن بُعد (بلا تحديث)

* **إعدادات عن بُعد:** حدود الخطط، النصوص، أعلام الميزات، الروابط، النموذج الذي يستخدمه الذكاء الاصطناعي، وكل ما لا يحتاج كودًا جديدًا. موقَّعة مثل التحديثات.

* **رسائل داخل التطبيق:** شريط أو نافذة بكل اللغات، لشريحة محددة، مع جدولة وانتهاء، وعدّاد «شوهدت وأُغلقت» بلا هوية المستخدم. أما الرسائل التسويقية بالبريد فتحتاج موافقة مسبقة، وتفصلها اللوحة عن الرسائل الضرورية.

* **وضع الصيانة:** يعرض رسالة ويوقف المزامنة والذكاء الاصطناعي فقط. التنضيف المحلي يبقى يعمل لأنه لا يحتاج الخادم.

* **أزرار الطوارئ المنفصلة:** إيقاف الدخول الجديد، أو الذكاء الاصطناعي، أو المزامنة، أو المشاركة، كلٌّ على حدة وبنقرة.

#### سادسًا: ما لا تفعله لوحة المالك (عمدًا) وسبب كل واحد

* **لا تقرأ محتوى ملفات العملاء ووصفاتهم المشفَّرة.** هذا سر ثقة الجهات الحساسة وحماية لك من مسؤولية بيانات لا تحتاجها. وإن أردت لمؤسسة معيّنة «استردادًا بالضمان» (`key escrow`) فهو خيار تفعّله لكل مساحة عمل بموافقة العميل الصريحة وبعد استشارة قانونية، ويبقى مغلقًا افتراضيًا.

* **لا توقّع تحديثًا بدون مفتاح الأمان.** مفتاح التوقيع في خدمة معزولة (AWS KMS) لا تصدر توقيعًا إلا بعد موافقتك بمفتاح الأمان المادي (YubiKey 5 FIPS)، ولوحة المالك نفسها لا تملكه. فلو اخترق أحد اللوحة لا يستطيع دفع تحديث خبيث لكل المستخدمين، وهذا أخطر سيناريو في المشروع كله.

* **لا انتحال شخصية مستخدم.**

* **لا حذف ولا تعديل لسجل التدقيق.**

#### سابعًا: حماية حساب المالك نفسه

حساب بكل هذه القوة هو أهم هدف للمهاجمين وأخطر نقطة فشل في المشروع، لذلك:

* مفتاحا أمان مادّيان، أساسي معك واحتياطي في مكان آمن، مع حساب طوارئ (9.6).

* تنبيه فوري على هاتفك عند أي دخول، وقيود على الجهاز والشبكة، وجلسة قصيرة، وإعادة مصادقة للإجراءات الحساسة.

* موافقة شخصين اختيارية على التحديثات الإجبارية حين يوجد مشرف ثانٍ.

* **خطة استمرارية:** وثيقة مختومة عند شخص موثوق تشرح كيف يُستعاد التحكم إن ضاعت المفاتيح أو أصابك مكروه (يرتبط بخطر «الاعتماد عليك وحدك» في القسم 13).

* **سجل إصدارات شفاف:** كل إصدار منشور يُسجَّل في سجل عام قابل للتحقق، فيستطيع أي طرف مراجعة ما نُشر.
