# Task P0.01 — Account, device, and subscription data model

## Objective
Establish the server-owned identity and billing schema without uploading or storing customer spreadsheet/file contents.

## Tables and constraints
- `user_credentials`: one Argon2id password hash per user; the raw password is never persisted.
- `email_verification_tokens` and `password_reset_tokens`: one-time 32-byte token hashes, expiry, and consumption state.
- `devices`: workspace/user-scoped device metadata and installation-key hash; one active device record per user.
- `plans`: Free plus draft personal/team/enterprise plan codes. Paid prices remain unset and draft until approved.
- `subscriptions`: workspace-scoped subscription history with one current subscription per workspace.
- `billing_webhook_events`: provider/event idempotency and payload hash only; raw customer file content is excluded.

## Existing data
- Adds `users.email_verified_at`.
- Backfills a current Free/known-plan subscription for existing workspaces that have no current subscription.
- Does not rewrite customer-owned file data or existing plan labels.

## Security
- Credential, token, and installation secrets are represented by hashes, not plaintext.
- Workspace-owned device/subscription data has forced RLS policies.
- Credential records are user-scoped through `app.user_id`.
- Team/enterprise tiers are catalogued for future extension, not enabled commercially in this task.

## Rollback
The matching `0003_accounts_subscriptions_devices.down.sql` removes all new tables and the added user column. It is intentionally separate from applying the migration; no live database is changed by this code commit.

## Acceptance
- Migration verifier passes up/down pairing, UUIDv7, and RLS checks.
- CI Rust/Python/web checks pass.
- Database apply/rollback is tested against PostgreSQL 18 before enabling production accounts.
