# P0.03 — ربط تطبيق SafiData بهوية الموقع

## الهدف
استخدام حساب SafiData نفسه في الموقع وتطبيق سطح المكتب، بحيث تتصل شاشة إنشاء الحساب وتسجيل الدخول والتحقق من البريد وتسجيل الخروج في التطبيق المحلي بخدمة الحسابات المشتركة التي أُنشئت في P0.02.

## السياق الحالي
- واجهة الموقع والتطبيق مبنيتان من واجهة React واحدة.
- الموقع يستخدم نقاط API نسبية من نفس النطاق: `/v1/auth/*`.
- تطبيق Tauri يحمّل الواجهة من أصل محلي، لذلك الطلب النسبي في النسخة المثبّتة لا يصل تلقائيًا إلى خادم الموقع.
- P0.02 أبقى رمز الجلسة في ذاكرة الصفحة فقط، ولم ينفذ ربط جلسات سطح المكتب.
- P0.04 مسؤول عن سياسة الجهاز/الجلسة الواحدة، ولا يجوز تنفيذها هنا.

## النطاق المسموح
1. جعل عميل المصادقة المشترك يدعم مسارين:
   - الموقع وبيئة التطوير: `/v1/auth/*` من نفس الأصل، مع الإبقاء على Vite proxy المحلي.
   - تطبيق سطح المكتب المثبّت: `https://<configured-api-origin>/v1/auth/*`، من عنوان API يُمرر وقت بناء حزمة سطح المكتب فقط.
2. التحقق الصارم من عنوان API: أصل HTTPS فقط، بلا مسار أو بيانات اعتماد أو query أو fragment أو wildcard أو عنوان IP/localhost. يُرفض أي عنوان غير مطابق.
3. تمرير الأصل المسموح وحده إلى سياسة CSP الخاصة بتطبيق سطح المكتب؛ لا يُسمح باستخدام `https:` بشكل عام.
4. إضافة CORS إلى الخادم لأصول Tauri المعروفة وأصل تطوير سطح المكتب المحلي فقط. السماح المسبق محدد بالطرق والرؤوس التي تحتاجها شاشة الحساب، دون wildcard ودون cookies/credentials.
5. ربط واجهة الحساب الحالية في تطبيق سطح المكتب بنفس endpoints التي يستخدمها الموقع، مع رسائل واضحة عندما لا يكون عنوان API مضبوطًا.
6. الإبقاء على رمز الجلسة في ذاكرة React فقط، وعدم كتابته إلى localStorage أو sessionStorage أو IndexedDB أو cookies أو ملفات التطبيق.
7. توثيق متغيرات البناء والتشغيل المطلوبة، واختبار سلوك الموقع وسطح المكتب وCSP وCORS.

## خارج النطاق صراحةً
- حظر الحساب من العمل على جهازين أو إبطال جلسات الأجهزة الأخرى (P0.04).
- منع فتح التطبيق قبل المصادقة أو فرض شاشة الدخول كحاجز إقلاع (P0.05).
- المزامنة السحابية أو رفع الملفات/محتوى الجداول/الوصفات إلى الخادم.
- التخزين الدائم لرمز الجلسة أو استخدام مخزن كلمات المرور في نظام التشغيل.
- تغيير قاعدة البيانات أو مخطط الحسابات أو منطق الاشتراكات في P0.01/P0.02.
- إعداد DNS أو شراء نطاق أو نشر الخادم أو الموقع أو إعداد بيانات SMTP الفعلية.

## معايير القبول
- الموقع يستمر في استخدام `/v1/auth/*` دون تغيير سلوكه.
- تطبيق سطح المكتب يستخدم نفس حسابات الموقع ونقاط P0.02 عند ضبط `SAFI_API_BASE_URL`.
- النسخة المثبّتة لا تعود بصمت إلى عنوان محلي خاطئ عند غياب الإعداد؛ بل تعرض خطأ إعداد واضحًا.
- حزمة Release لسطح المكتب لا تُبنى دون عنوان API صالح عبر HTTPS.
- CSP لا تسمح إلا بأصل API المضبوط، مع بقاء بقية سياسة الأمان كما هي.
- CORS يقبل أصول Tauri الموثوقة والطلبات المسبقة المطلوبة فقط، ويرفض الأصل والطريقة والرؤوس غير المصرح بها.
- لا يُخزن رمز الجلسة الدائم، ولا تُرسل بيانات الملفات أو محتواها إلى الخادم.
- اختبارات Rust وTypeScript وعمليات CI ذات الصلة تنجح.
- لا يتم نشر أي شيء إلى الإنتاج ولا تنفيذ أي ترحيل لقاعدة الإنتاج.
