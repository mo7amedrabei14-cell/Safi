# STUDIO-Phase-2 — Guided AI Compiler

**الحالة:** لم يبدأ؛ يعتمد على اجتياز [Phase 1](STUDIO-Phase-1.md) بالكامل.

## الهدف والنطاق

طلبات عربية وإنجليزية تتحول إلى DSL محدود يحققه وينفذه Rust. الذكاء يصوغ اقتراحًا ولا يحسب رقمًا تحليليًا أو ينشئ VerifiedMetricToken.

## المتطلبات

- شريط أوامر طبيعي للتحليل والتجميع والمقارنة والشرائح والتقرير، عبر User Prompt → AI Interpretation → Structured DSL → Rust Validation → Rust Execution → Verified Results.
- مخطط DSL إصـداري محدود الأوامر؛ لا JavaScript/Rust/SQL حر أو وصول للملفات والنظام خارج الصلاحية.
- تحقق Rust من المصادر والأعمدة والأنواع والعمليات والصلاحيات وحدود الموارد والمعادلات ومراجع المؤشرات. رفض ذري بلا تنفيذ جزئي.
- لا تغيير لقيمة metric عبر AI. غياب البيانات حالة ظاهرة، والتوقعات والافتراضات مميزة عن الفعلي.
- سرد بعناصر نصية ومراجع `{{metric:...}}`؛ تحديث حي، عربي/إنجليزي، عناوين وقوائم وتنسيق، وكشف المراجع المفقودة ومنع تصديرها دون تنبيه واضح.
- فصل نص المستخدم عن اقتراح AI في نموذج المحتوى وتاريخه.
- اكتشاف المفقود والمكرر وخارج النطاق وتناقض الأعمدة والتواريخ غير المنطقية ومخالفة الأنواع والشذوذ الإحصائي.
- كل Finding يحمل المشكلة والصفوف والسبب والطريقة والتصحيح المقترح والأثر المتوقع. لا تصحيح للأصل ولا تنفيذ بلا موافقة؛ يسجل كتغيير قابل للتراجع.
- Local-Only يبقى الافتراضي؛ لا إرسال لبيانات المستخدم إلى مزود خارجي أو إضافة موافقة/خدمة جديدة خارج النطاق.

## القبول

1. اختبارات تكامل تثبت تفسيرًا فعليًا للطلبات الصحيحة، لا مطابقة كلمات شكلية تدّعي AI.
2. رفض الأوامر والموارد والمراجع المخالفة، وعدم تنفيذ كود حر أو جزء من أمر مرفوض.
3. لا يستطيع ناتج AI إنشاء token أو تغيير حساب Rust.
4. النصوص تتحدث بتغير المقاييس، والمراجع المفقودة تُكتشف قبل التصدير.
5. اقتراح الشذوذ لا يغير البيانات قبل موافقة المستخدم، ويمكن التراجع عن التصحيح.
6. جميع العمليات الحسابية تنفذ في Rust؛ لا الانتقال إلى Phase 3 قبل النجاح.
