# STUDIO-Phase-5 — Integration, Reliability & Green Gate

**الحالة:** لم يبدأ؛ يعتمد على اجتياز [Phase 4](STUDIO-Phase-4.md).

## الدمج المطلوب

- الاستوديو جزء من التطبيق الفعلي: SmartDropzone → مصدر مشروع → Views مترابطة داخل ApplicationShell الحالي.
- لا استوديو قبل المصادقة، ولا دخول بديل أو تجاوز للصلاحيات أو هوية الجهاز أو الاستحقاق الموجود.
- لا تغيير للموقع التسويقي أو مخطط قاعدة البيانات أو تاريخ migrations أو سياسات الأمان أو الاشتراكات.
- عدم وجود بيانات تجريبية في مسار النتائج أو واجهات منفصلة تتظاهر بالدمج.

## بوابة القبول

1. جميع اختبارات DataGraph والقيم والمراجع والحتمية والاعتمادات والتراجع وstale والعبث ناجحة.
2. اختبارات DSL والأوامر المحظورة والسرد والشذوذ تثبت حساب Rust وعدم اختلاق AI للأرقام.
3. اختبارات تحرير الجدول والرسوم والتصفية والشرائح والمستند وFree-Form ناجحة.
4. حفظ واستعادة وإعادة فتح المشاريع والمراجع والأصول والإصدارات دون فقد.
5. تصدير Offline وأمان وصحة بيانات وتوافق متصفح مثبتة بالفعل.
6. اختبارات Authentication/Authorization/Device Identity/Entitlement/Shell دون تعديل السياسة أو ادعاء وجود حارس غير منفذ.
7. Benchmark لأحجام متعددة يسجل الاستيراد والتنظيف والحساب وتحديث المقاييس والرسوم والذاكرة واستجابة الواجهة والتصدير، مع البيئة وأحجام البيانات. لا أرقام تقديرية.
8. `make check` وفق Makefile وdocs/COMMANDS.md، مع pnpm test/build وcargo test/clippy/fmt وفحوص التكامل والمتصفح والتصدير.
9. تحقق مستقل من CI على SHA المدفوع إلى main؛ لا يكفي نجاح محلي أو رابط قديم.

## التسليم

- تقرير مرحلة عربي: التنفيذ والملفات والقرارات والأوامر والنتائج الفعلية وروابط CI والقياسات والقيود وغير المنفذ وCommit SHA.
- إنشاء `docs/reports/QUAD-STUDIO-FINAL-REPORT.md` فقط بعد اجتياز المراحل الخمس فعلًا.
- العمل main فقط بلا branches أو worktrees أو force push أو استبدال تغييرات المستخدم.
- لا Production Deployment. يجب التحقق من عدم تشغيل نشر تلقائي قبل أي push.
- لا P0.06 ولا أعمال خارج تكليف الاستوديو؛ التوقف عند التسليم وانتظار قبول المالك.
